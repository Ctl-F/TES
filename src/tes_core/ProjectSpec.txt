TES (Teris Entertainment System) — Technical Summary
Core Philosophy
Retro-inspired but not hardware-faithful; prioritizes determinism, performance, and clarity over strict emulation.
Explicit control > implicit behavior (no hidden side effects like MMIO-triggered writes).
Teaches discipline: minimal instruction set, manual responsibility for calling conventions and state.
Deterministic execution model with fixed cycle budgeting.
Extensible architecture (extensions + potential ISA profiles).
Avoid unnecessary abstraction layers; expose hardware-like concepts cleanly.

Virtual CPU: 1.17 Million Cycles Per Second (Fixed Frame FPS)
FPS is configurable e.g. it assignes slices of a second to auto gpu+input sync.
FPS can be set to 0 for headless mode and manual GPU+input sync.
Core Game development is fixed frame (fixed 15/30/60/other fps)
In headless mode a real-world timestamp can be obtained via syscall and dynamic frame (+ deltaTime) can be manually
used.

CPU Architecture
Registers
General Purpose (GP): R0–RF (16 registers, u4 originally; moving to u5 for expansion up to 32 total).
Stack Registers:
SP (stack pointer)
SB (stack base)
SH (stack high / limit)
User-visible in addressing, not directly assignable (must use controlled ops like stackset, bump).
Special Registers:
IP (instruction pointer)
JR (jump/link register)
FCL/FCH (frame cycle counter, low/high 16)
GCL/GCH (global cycle counter, low/high 16)
Register Encoding
Moving from u4 → u5:
Enables ~32 registers total.
Tradeoff: reduces immediate offset size.
Instruction width: 32 bits
8 bit opcode
Remaining bits: registers + immediates.
Control Flow Model
Branching
Single primitive: b (branch)
No separate jmp / call:
B writes return address to jr. Jr must be preserved if return is needed.
JR (Jump Register)
Only written by:
b, bt, bf (branch variants)
Must be manually preserved for function calls.
Calling Convention (ABI)

Standard pattern:

push jr
b func
...
func:
  ...
  pop jr
  b jr
JR can be freely clobbered inside functions if preserved.
Tail Calls
Equivalent cost:
pop jr; b target
pop jr; b jr
No dedicated optimization needed.
Alternative (unsafe but faster)
mov rf, jr
...
b rf
Avoids stack use, not recursion-safe.
Design Intent
No distinction between loops and functions at ISA level.
Differences are purely structural patterns, not instruction semantics.
Instruction Set Design
General
Minimal, composable primitives.
No memory-to-memory mov:
Cannot encode two full addresses in 32 bits.
Avoid partial/crippled support.
MOV Design
Unified handler with comptime specialization:
dst.* = src.*;
Variants differ only in how src/dst are resolved.
Addressing Modes
[reg]
[reg + const]
[pageReg, offsetReg + const]

Constraints:

const must be compile-time resolvable.
Expressions like a + b - c allowed if reducible at compile time.

pageReg uses the lower byte for page selecting. OffsetReg uses the full 16 bit width

Stack Addressing Rules
[SP + n] → allowed (implicit page 0)
[ra, SP + n] → disallowed (unsafe page ambiguity)
Memory Model
Layout
Total: 256 pages × 64KB = ~16MB RAM
Page 0:
General use + stack region
Page 255:
MMIO (devices)
Pages 1–254:
General-purpose RAM
Cartridge
Addressing: 16-bit page index × 64KB
Max size: ~4GB
Pages can be mapped into RAM (read-only).
Addressing Scheme
Page selector + 16-bit offset
Guarantees:
Exactly one valid address per byte.
No aliasing via offset overflow.
Page Mapping
Cartridge pages → RAM pages (read-only)
Enables:
Instant data swapping
No copy required
Page Templates (Key Feature)
Identical layout across pages
Swap data by changing page selector
Enables:
Instant level switching
Pointer reuse across datasets
Memory Operations
memcopy / memmove
Use:
src page + offset
dst page + offset
length register
No constant offsets (unlike mov)
Justified due to block semantics.
Execution Model
Deterministic instruction stepping
Cycle counter increments per instruction
Frame timing derived from cycle counts
No true parallelism (devices run between instructions conceptually)
Syscalls

Explicit invocation (syscall ID)

Vector Instructions reinterpret a 16 bit register as a 2x8bit register and perform parallel (non-overlapping) math on the two channels

Syscalls are for host interaction and must be a compile-time known constant
interrupts are handled by a small co-processor that freezes the main processor and executes a handler associated with the interrupt
code. This is for error handling and also debugging.  The co-processor has access to information about the main processor and
can make modifications to the main-processor (via special instructions) for error correction/handling. It also has 3 "return" policies:
retry
resume (skip instruction having performed the work the bad instruction would have done)
resume addr (resume at a different point in code abandoning the work that failed)
